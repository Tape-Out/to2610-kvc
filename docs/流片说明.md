# to2610-kvc 流片说明

流片说明报告（docx）的功能描述、寄存器含义、板级连接、测试说明与局限从这里取，只写在这一处。

## 功能描述

能跑 Linux 的单核芯片，面向 ECOS 2610 班车。片上是 Hirosh Dabui 的 KianV SoC：一颗多周期的 RV32IMA 核，带 Sv32 页表、M/S/U 三态、Zicntr 与 Sstc，外加串口、三路 SPI、一位 GPIO、CLINT、PLIC 与 SDRAM 控制器。这颗 SoC 在 GF180MCU 上经 wafer.space 流过片，这里整颗当黑盒接进来。上游的子模块不动，源码只带一个一行的补丁：机器态软件中断的挂起位原来不随 CLINT 的 `msip` 落下，一进中断就出不来（已报给上游）。

片上没有存储。程序放在片外的 SPI Flash 里，主存是片外一颗 32 MiB 的 SDRAM。焊上 Flash、SDRAM、50 MHz 晶振与 USB 转串口，烧好 Flash，上电就从串口进 Linux 的 shell；再接一张 SD 卡当根文件系统、一块 SPI 网卡模块，就是一台能上网的小主机。

### 功能一览

| 项 | 支持 | 说明 |
|:--:|:--:|:--:|
| 指令集 | RV32IMA、Zicsr、Zifencei、Zicntr、Sstc | 多周期实现，一条指令若干拍；没有压缩指令，没有浮点 |
| 特权级与虚存 | M、S、U 三态，Sv32 | 取指与访存各一个 32 项的 TLB，硬件走页表 |
| 主存 | 片外 SDRAM 32 MiB | 16 位数据线，4 个 bank、13 位行、9 位列，CAS 延迟 2；控制器在片上，时序拍数按 50 MHz 算 |
| 程序存储 | 片外 SPI Flash，16 MiB 窗口 | 只读，普通读命令 `0x03`，单线；复位后从 `0x2010_0000` 取指，即 Flash 的 1 MiB 处 |
| 串口 | 1 路 | 8N1；波特率由软件写分频寄存器，引导程序设成 115200 |
| SPI0 | 主口，1 个片选 | 接 SD 卡（SPI 模式），Linux 里是 `mmc_spi` |
| SPI1 | 主口，1 个片选 | 接 SPI 网卡 W5500 或 ENC28J60，Linux 里有现成驱动；也可以接别的 SPI 从设备，比如 gpu、交换机、路由器的管理口。复位后 SCK 是主频的一半，管理口要不超过它主频的八分之一，`spimode dev`、`spimode gpu` 先把分频设成 5 |
| GPIO | 1 位，可设方向 | Linux 里经 `/sys/class/gpio` 用 |
| 计时器与中断 | CLINT、PLIC | 计时器每微秒走一格；串口接 PLIC 的 10 号源 |
| 重启 | 写 `0x1110_0000` | `0x7777` 重启，Linux 里是 `reboot`。`0x5555` 片上不认：`poweroff` 写了它之后内核停住，电要板上去断 |

### 启动流程

1. 复位放开后，片上先数 333,333 拍（50 MHz 下 6.7 毫秒），再给 SDRAM 上电初始化（200 微秒、预充电、两次刷新、写模式寄存器）。
2. 核从 Flash 的 `0x2010_0000` 取指，这里放的是引导程序 `sw/boot`。它在 Flash 里就地执行：照主频寄存器把串口设成 115200，打出 `to2610 boot`。
3. 引导程序读 Flash 里紧跟在自己后面、1 MiB 又 64 KiB 处的 16 字节头（魔数、字节数、校验和），把后面的载荷搬到 SDRAM 起始处 `0x8000_0000`。从 Flash 取一条指令要一百多拍，所以搬运的那个循环先拷进 SDRAM 再执行；每搬 64 KiB 打一个点。
4. 校验和对上就跳到 `0x8000_0000`，对不上就打出两个数并停住。
5. 载荷是 OpenSBI 带着 Linux 内核与设备树（`fw_payload.bin`）。内核从串口出控制台，根文件系统取内核里带的，或 SD 卡第二个分区。串口驱动起来之前的内核日志经 OpenSBI 打出来（`earlycon=sbi`），所以 OpenSBI 的抬头之后紧跟着就是 `Linux version` 那一行；上板时停在哪一步，看最后一行日志就知道。

### 软件

| 件 | 来源 |
|:--:|:--:|
| 引导程序 | 本仓 `sw/boot`，裸机 C，不到 1 KiB |
| OpenSBI 1.4 | 上游 buildroot 配方里的 KianV 平台补丁 |
| Linux 7.1-rc1 | 上游配方里的 KianV 补丁（Sv32 的支持、SPI 与 GPIO 驱动）与内核配置；本仓加几项配置（`sw/linux/linux.fragment`：SBI 的早期控制台、根文件系统不压缩、spidev、FAT）与两个补丁（`sw/linux/patches`：SPI 控制器的驱动认 `SPI_CS_HIGH`，SD 卡上电时要在片选抬高的情况下送时钟；GPIO 驱动照这颗片上的一位口子读写） |
| 根文件系统 | buildroot，busybox 为主；本仓加 `spix`、`spimode`、`sdcard`、`tgpu`、`apptest` 五个命令，SD 卡第一个分区上的 `boot.sh` 上电自动执行；内核另带 `to2610-gpu` 的驱动（`/dev/tgpu`） |

`sw/linux/build.sh` 照上游配方编出全部镜像，`sw/pack.py` 拼出 Flash 镜像，`sw/flash.sh` 用 CH341A 烧进去，`sw/console.sh` 开串口。

## 寄存器

片上的外设是上游自己写的，没有息壤的寄存器图，地址照上游的 `defines_soc.vh`。

| 地址 | 内容 |
|:--:|:--:|
| `0x0200_0000` | CLINT：`msip`、`mtimecmp`、`mtime` |
| `0x0C00_0000` | PLIC：上下文 0 给 M 态，上下文 1 给 S 态 |
| `0x1000_0000` | 串口数据：写是发，读是收，没收到字时读出全 1 |
| `0x1000_0005` | 串口线路状态：位 0 收到字，位 5 发送保持空，位 6 发送空 |
| `0x1000_000C` | 分频一：低 16 位是串口的分频值（每位占它加一拍），高 16 位是 SPI0 的分频；复位值 1 |
| `0x1000_0010` | 分频二：低 16 位是计时器分频（1 即每微秒一格），高 16 位是 SPI1 的分频；复位值 1 |
| `0x1000_0014` | 主频，兆赫，8.8 定点；50 MHz 读出 `0x3200` |
| `0x1000_0018` | SDRAM 字节数，读出 `0x0200_0000` |
| `0x1000_0700`、`0704`、`0708` | GPIO 方向、输出、输入 |
| `0x1050_0000`、`0004` | SPI0 控制、数据 |
| `0x1050_0100`、`0104` | SPI1 控制、数据 |
| `0x1060_0000` | SDRAM 控制器的运行时设置：各项时序拍数、读数据在哪个沿采 |
| `0x1110_0000` | 写 `0x7777` 重启 |
| `0x2000_0000` 起 16 MiB | SPI Flash，只读 |
| `0x8000_0000` 起 32 MiB | SDRAM |

## 板级连接

电平与驱动能力以 ECOS 给的焊盘手册为准，下面的器件都按 3.3 V 选。payload 第 n 位就是封装上的 `user_io[n + 7]`；`user_io[6:0]` 是设计编号，复位期间由板上的拨码给。

| payload 位 | 方向 | 信号 | 接到 |
|:--:|:--:|:--:|:--:|
| 0 | 入 | 串口 RX | USB 转串口（CH340、CP2102）的 TXD |
| 1 | 入 | SPI0 MISO | SD 卡座 DAT0 |
| 2 | 入 | Flash MISO | W25Q128JV 的 DO（脚 2） |
| 3 | 入 | SPI1 MISO | W5500 模块的 MISO |
| 4 | 出 | 串口 TX | USB 转串口的 RXD |
| 5、6、7 | 出 | SPI0 片选、时钟、MOSI | SD 卡座 CD/DAT3、CLK、CMD；DAT1、DAT2 上拉 |
| 8、9、10 | 出 | Flash 片选、时钟、MOSI | W25Q128JV 的 CS（脚 1）、CLK（脚 6）、DI（脚 5）；WP 与 HOLD 上拉 |
| 11、12、13 | 出 | SPI1 片选、时钟、MOSI | W5500 模块的 SCSn、SCLK、MOSI |
| 14 | 出 | SDRAM 时钟 | CLK；它是主时钟取反 |
| 15 | 出 | SDRAM CKE | CKE |
| 16、17 | 出 | DQM[1:0] | LDQM、UDQM |
| 18 至 30 | 出 | A[12:0] | A0 至 A12 |
| 31、32 | 出 | BA[1:0] | BA0、BA1 |
| 33、34、35、36 | 出 | CS、WE、RAS、CAS | 同名脚，低有效 |
| 37 至 52 | 双向 | DQ[15:0] | DQ0 至 DQ15 |
| 53 | 双向 | GPIO | 排针，或一颗 LED |
| 54 至 65 | — | 没用到 | 高阻，悬空即可 |

- **SDRAM**：256 Mbit、16 位、4 bank、13 位行 9 位列的 SDR SDRAM，例如 W9825G6KH-6、IS42S16160J-6、AS4C16M16SA-6，与上游用的 MT48LC16M16A2 同一种组织。走线尽量短，时钟线与数据线等长。
- **Flash**：W25Q128JV 或任何支持 `0x03` 读的 16 MiB SPI NOR。片上的 Flash 时钟是主频的一半，50 MHz 下 25 MHz。
- **时钟**：50 MHz 有源晶振直接给芯片的时钟脚。片上的 SDRAM 时序与软件读到的主频都按 50 MHz 算，换别的频率要重新出片。
- **网卡**：带网络变压器与 8P8C 插座的 W5500 模块，百兆以太网只用插座的 1、2、3、6 四根线。
- **烧 Flash**：按住复位，这颗的全部引脚都是高阻，Flash 的四根线就让出来了；用 CH341A 夹在 Flash 上写 `flash.bin`，写完松开复位就从它启动。板上给复位留一个按键或跳线，Flash 的四根线各留一个测试点。在共享封装里，把设计编号拨到没人用的号也是同样的效果。
- **复位期间的电平**：引脚全部高阻，所以 Flash 的 CS、SDRAM 的 CS、串口 TX 各接一颗 10 kΩ 上拉，免得烧录与上电过程里它们悬空。

## 测试说明

测试台 `tb.cpp` 来自黑盒仓，跑在 Verilator 上。片外的三样东西按引脚电平建模：SDRAM 模型认全部命令、突发长度与 CAS 延迟照模式寄存器；Flash 模型认 `0x03` 读；串口模型按 115200 收发。被测的是 `ran asic` 出的那份交付文件，测试台的每根线照 `report.json` 的位表接到五口顶层上。

| 用例 | 测什么 |
|:--:|:--:|
| hello | 裸机程序从 Flash 就地执行：设串口分频，1024 个字按素数步长散在 16 MiB 里写了再读，字节写与半字写不动旁边的位，读主频与内存大小寄存器 |
| isa | 标准 riscv-tests（`p` 环境，rv32ui、um、ua、mi、si）逐个在这份 `.v` 上跑：程序放进 SDRAM 模型，Flash 里两条指令跳过去，测试台盯 `tohost`。79 个全过；5 个不适用（Zacas、硬件非对齐访存、PMP、调试触发器） |
| arch-test | riscv-arch-test（ACT4）的非特权部分，跑法同上：I、M、Zmmul、Zaamo、Zalrsc、Zicsr、Zifencei、Zicntr 共 71 个自检程序，期望值出自 Sail 模型、编进程序里，不对时程序把错的寄存器打到串口。71 个全过 |
| periph | 裸机程序把片上外设逐个点一遍。GPIO：输出高低各读回一次，松手后读到板上的上拉。SPI0、SPI1：测试台上各挂一个回声从设备（每个字节回上一个字节的反码，片选一抬就忘），收发四个字节、中间重拉一次片选，片选、时钟、收发四根线与位次都对才回得对。计时器：`mtime` 与 `time` 寄存器是同一个数，到点进中断。软件中断：写 `msip` 进一次中断，处理程序清掉它之后不再进来，`mip` 的那一位跟着落下。PLIC：串口发字期间进外部中断，领到 10 号。重启：写 `0x7777` 后从复位向量再起 |
| boot | 引导程序把载荷从 Flash 搬进 SDRAM，校验和对上后跳过去；载荷是一段回显程序，测试台从串口发字、核对回显，串口的收发两个方向都走到 |
| rtos | FreeRTOS（V11.2.0，只在机器态）由引导程序搬进 SDRAM 后起来：一个任务每 3 拍往队列里发一个数，一个收了从串口报，一个最低优先级的任务不让出、只有抢占起作用别人才轮得到。节拍来自 CLINT 的计时器中断，任务让出走 `ecall`，串口由互斥量护着。五个数收齐、所花节拍数在范围内才算过 |
| image | 载荷里的内核带着根文件系统先在 QEMU 的 virt 机器上起到 shell。只验软件：根文件系统没嵌进去、init 起不来这一类一分钟内拦下，不必等到下一段 |
| linux | 引导程序搬的是 OpenSBI 加 Linux，起到 shell 的提示符后跑一组命令：算术、`uname`、`/proc/cpuinfo` 里的 `sv32`、写文件再算 md5、内存总量、`seq` 接 `awk` 的管道、`dd` 接 `md5sum`、睡一秒再数计时器中断、`ping` 本机回环、卡座上没卡时驱动已经摘下且内核日志里没有 SPI 模式的报错、经 sysfs 把 GPIO 脚拉高拉低并读回；再跑 `apptest` 的十项（fork 与退出码、管道传 16 KiB 核校验、信号处理与杀子进程、共享匿名映射跨 fork、四个线程的互斥锁与原子加、文件读写改名删除、软浮点求和逐位比、单调时钟与睡眠、本地套接字、exec 退出码），最后 `reboot`，引导程序的抬头再出来一次 |

起到 shell 时存一次断点，下面几段都从断点接着跑（`htest/linux-layers.sh`；流水线上一段一个作业，同时跑，每段都在托管机一个作业的六小时以内）。测试台多了三样片外器件：SPI 模式的 SD 卡、W5500 网卡（对面可以是测试台里一台应 ARP、ping、DHCP 的主机，也可以经两个文件接到另一个仿真上）、一整颗 `to2610-gpu` 的网表。

| 用例 | 测什么 |
|:--:|:--:|
| sdcard | SPI0 上插一张 FAT16 的卡：`mmc_spi` 认卡、挂载、读文件、64 KiB 的 md5、写文件、重挂再读；跑完从卡的镜像里取出芯片写的那个文件核对 |
| network | SPI1 上接 W5500：`spimode net` 重新探测网卡，`ip link` 改 MAC，`udhcpc` 向测试台里的主机要到 10.0.0.2，`ping` 它三次都回 |
| netjoin | 网线接到 `to2610-switch` 两颗夹 `to2610-router` 的联合仿真上：照 `future-work/04` 的 L4 定 MAC、配地址与 MTU、加路由，同网段 ping A0（TTL 64）、过路由器 ping B0（TTL 63） |
| netinet | 同上，B0 换成托管机上的一块 TAP 网卡（真的 TCP/IP，替 10.0.0.0/24 做 NAT）：过路由器 ping 它、TCP 取一个 8 KiB 的文件核 md5、经 NAT 向 8.8.8.8 查 DNS、按名字取 example.com 的页面 |
| gpujoin | SPI1 上接一整颗 `to2610-gpu`：`spimode dev` 换成 spidev，`spix` 重放主机录下的装载、起跑、查状态、读回与开视频，读回的数据存储与软件模型逐字节相同，三个视频寄存器读回写进去的值 |
| gpudrv | 同一颗 gpu 走内核驱动：`spimode gpu` 绑上 `to2610_gpu`，`tgpu info` 回四核、每块四线程，`tgpu run` 跑渲染（`shade`）与推理（`mlp`）各一遍、读回与软件模型逐字节相同，再经驱动设两种视频格式 |

黑盒仓在上游源码（加补丁）上把 hello、periph、isa、arch-test 四样在 TLB 条目数与主频各取几档共 11 个点上各跑一遍。`kianriscv` 仓跑的 riscv-tests 用的是上游 FPGA 仓里的另一份核，与这颗里的不是同一份源码，不算在这颗头上。

## 局限

- 上游的指令与数据缓存建在 GF180MCU 的 SRAM 宏上，MPC-Frame 不许带硬宏，这里把缓存旁路了。每次取指与访存都到片外 SDRAM，比上游流片的那一版慢。
- 主频写死 50 MHz。SDRAM 的读数据在时钟下降沿采，留给焊盘、走线与 SDRAM 的时间只有半拍 10 纳秒；上板若读错，先在 `0x1060_0000` 把采样改到上升沿或加一拍。
- 串口的波特率寄存器复位值是 1，Flash 里没有引导程序时串口不出字。
- 核：黑盒仓在上游源码上打了十三个补丁（细目在黑盒仓的 README），都是 riscv-tests 与 riscv-arch-test 查出的与规范不符之处，修完两套全过。页表项的 A、D 位由软件置（Svade），Linux 本来就这样处理。没有 PMP，没有调试触发器。
- GPIO 的方向与输出写在第 9 位，读回在第 0 位，这是上游硬件的写法。上游的 Linux 驱动是按 FPGA 版每线一位写的，在这颗片上拉不动这根脚；镜像里给驱动打了补丁（`sw/linux/patches`），Linux 里就是一根线的 `gpiochip`。
- 只有一位 GPIO、一路串口。payload 还空着 12 位，但上游的顶层没有再多的外设可接。
- 网口不在片上，靠 SPI 网卡模块；SD 卡走 SPI 模式，速度有限。卡座没有插拔检测脚：卡在上电前插好，上电时没认到卡系统会把驱动摘下来，之后才插的跑一次 `sdcard`。
- 串口没有接收缓冲。内核往控制台打字的几毫秒里连着到的第二个字会丢：手敲没事，成段粘贴时终端里设每字符 12 毫秒以上的发送延时。
- Flash 只读、单线。写 Flash 要靠片外的烧录器。
